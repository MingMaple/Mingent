# mingmem 运行规则（给人读的，**代码不引用本文件**）

> 这份文件只为一件事：让接任的会话/人快速理解「这个内核怎么改才不坏」。
> 内核本体保持洁净 —— 代码不读本文件、不读 `docs/`，删掉这些文档内核照样跑。

## 1. 这是什么

一个**自包含的本地记忆内核**：append-only JSONL 事件流是唯一真相源，SQLite 只是可重建投影。
纯 Python 3 标准库、零第三方依赖。**不是 skill 库**：没有 `SKILL.md`，也不打算有；
将来进 DSH harness 时以**插件**形式接入（插件只是外包装，内置整个内核）。

## 2. 硬边界

1. **真实数据根不许当实验场**：任何测试一律用 `tempfile` 临时根，或 `MINGMEM_CONFIG` 指向临时配置文件。
2. **不写本目录外的项目**；`记忆内核库/` 下除 `mingmem/` 之外的文件（`_Scripts/mem.py`、旧 `RULES/SKILL/_Docs`、`_Data/`）是**冻结档案**：只读，不改。
3. **冻结 ≠ 不许新增**：不新增/不改旧文件即可；`mingmem/` 本身就在库里，是本项目的在役代码。
4. 删文件、改事件流格式这类破坏性动作，先快照，并且要有用户明确同意。

## 3. 改动流程（照做就不会出错）

~~~~
cd <仓根本目录>                            # 本文件所在目录，不依赖工作区的任何其他路径
python -X utf8 -m mingmem selftest        # 基线：应 66/66（不需要数据根、不需要配置）
python -X utf8 -m mingmem.eval --gate     # 基线：应 rc=0
...改代码...
python -X utf8 -m mingmem selftest        # 必过
python -X utf8 -m mingmem.eval --gate     # 必过；若指标变化，先解释清楚再决定是否 --save-baseline
python -X utf8 -m mingmem doctor          # 事件↔投影对账 + 哈希链必须一致
python -X utf8 -m mingmem verify          # 事件链完整
~~~~

**只在有意改动引擎、并复核过指标变化之后**才允许 `--save-baseline`；拿它绕门禁等于自废武功。

## 4. 几条不能违反的不变量

1. 事件流只追加，不改写（唯一的例外是 `purge` 真删：它是有意设计的物理清理，且审计只留 id 哈希；
   **重写后必须重串哈希链**，否则一次合法的真删会被 `verify` 报成链断裂）。
2. 投影随时可丢：`rebuild` 之后检索顺序与强度必须复原（自检覆盖）。
3. 检索默认只取 active：`archived=0`、`superseded=0`、`erased=0`、`private/ask` 不出现。
4. **软删后没有任何检索旁路**；只有 `bin` 能列出、`links --id` 能精确访问并标注。
5. 写入必须原子：单事件 `O_APPEND` + `fsync`；命令级持数据根锁（可重入），持锁期间有心跳续命 ——
   否则长命令（`rebuild`/`purge`）会被别的进程当成残留锁清掉，互斥失效。
   每条事件 `prev_hash` 在**锁内**计算，不能在锁外算。
6. 数据根必须显式：`--data-root` > `MINGMEM_DATA` > `MEM_DATA`（兼容）> 配置文件；都没有就退出码 2。
7. 默认命名空间：项目层优先（`project:<目录名>`），`global` 必须显式写。
8. 审计类事件（`consent`/`forget`/`restore`/`purge`）与派生类（`access`/`sweep`/`archive`/`link`/`correction`/`consolidate`）
   **不许由 `add` 手写**：允许手写就等于允许伪造「用户同意了」「这条已真删」。
   （唯一例外是 `import` 子命令：它把 v1 旧库的历史翻译成事件，是迁移不是手写；别给 `add` 开口子。）
9. 后两层接口（`serve --stdio` / `MemoryCore`）**只许转发**给 `cli.main`：把业务逻辑写进接口层，
   等于让三层各自演化、行为必然分叉。失败必须抛异常/非零 `code`，不许静默返回空。
10. **参数的唯一来源是 argparse**：`spec.COMMANDS` 只放语义（summary/writes/remote/notes），
   参数由 `describe()` 从 parser 抽。新增/改参数必须同时：parser → spec（如需语义）→
   `JSON_SUPPORTED`（如需 --json）→ 实现 → 自检 → 文档 → 版本号。**自检 P1 项会抓漂移。**
11. 对外契约在 `docs/接口规范.md`（协议 `mmp/1`）：信封字段、`kind` 枚举、op 列表都算 API，
   改它们等于改协议，必须升协议大版本 + 出归档。

## 5. 常用命令

~~~~
python -X utf8 -m mingmem init --data-root <目录>   # 首次：写用户级配置
python -X utf8 -m mingmem add --ns project:x --kind note --text "..."
python -X utf8 -m mingmem recall --query "..." --json
python -X utf8 -m mingmem forget --ids <id>  ／ bin ／ restore ／ purge --ids <id> --yes
python -X utf8 -m mingmem status --json ／ doctor ／ cycle ／ rebuild
~~~~

长期决策在库外 `_Project_Meta/记忆内核/Project_Overview.md`（D1–D29），进度与坑点在 `Handover.md`。

## 7. 环境

Windows 上务必 `python -X utf8`（或 `PYTHONUTF8=1`）；Linux/macOS 无此要求。
调用方若从别的工作目录跑，需要 `PYTHONPATH` 指向本仓根，或 `pip install -e .` 后用 `mingmem`。

## 5. 运行期省 token（通用约束 v5）

**运行期省 token（通用约束 v5，2026-10-12 定、2026-10-13 三次修订（补第 8 条「不可逆动作的最小充分核验」、第 9 条「防步数失控三条」）；用户 2026-10-12 要求做成项目无关的通用限制并同步全部在役项目，数值由全局按 27 个退役会话跨项目实测迭代定）**

运行期按**步数**花钱：实测成本 ≈ **步数 × 每步约 1.7k token**（四分位 1.3k–2.0k，最高 3.3k），
与项目类型、会话角色无关。⇒ 唯一可伸缩的杠杆是**步数**。
1. **单轮工具调用 ≤ 20 步**。实测正常轮的中位数只有 **7 步**；>20 步的轮占 15%，却是账单主体。
   超了就停：先把「建一小段 → 跑一次 → 看一眼」固化成一条不变量，再继续。
2. **同一动作在本会话第 3 次出现，就固化成 `_Scripts/` 下的命令**，之后只许调参调用、不许现场重写。
   （实测：近似重复动作只占 1.8%，但出现过单个动作重复 11 次的实例 —— 这条是抓长尾。）
3. **一条命令验多个假设**，不要一步一问。
4. **脚本输出要「读一次就能决定下一步」**，不要打印全量清单。
   （实测：平均每个会话有 12.6 条 >4 KB 的工具返回，最大 54 KB。它的代价不在被重复读 —— 339 条里
   近似重复 0 条 —— 而在此后**每一步都要把它重读一遍**。）
5. **任务开始用 `todo_write` 列出计划**，让用户看得见总步数与进度。
6. **跨版本对比 / 一次性实验先隔离运行根**：把待跑的脚本与数据**整体复制到库根之外的独立副本**再跑
   （系统临时目录即可）。判据＝**这个脚本的库根会解析到哪**；只要可能落到真库或归档目录，就先复制。
7. **构建期可以铺张**（反复试错），不必为省 token 牺牲效率。
8. **不可逆动作的最小充分核验**：不要求「重查一遍」，只要求动手前能回答四问 —— **目标**（动谁）、**范围**（动多少）、
   **时效**（依据是否本会话内 / 无后续写入 / 无并发）、**逃生**（错了能否恢复）。四问都能从上下文回答 ⇒ 直接做，依据一句；
   **缺哪项只补哪项**；**逃生＝不可恢复**才升级为全量清单 ＋ 备份 ＋ 试运行 ＋ 用户确认。
   **本会话内用户亲口说的、或你自己刚跑出来的**信息**计入**核验，不得重复核验。判不准时先给拟做动作与依据、
   指出缺口，再问是否补查 —— 不要用「我不猜，先检查」开场。
9. **防步数失控三条（电脑侧 A/B 实测；第 1 条约束的补丁）**。实测：单轮 ≤20 步**两版都落到 33–36 步**，说明「超了就停」是事后话 ⇒ 改成事前拦：
   ① **动手前写步数预算**（"这活我打算 ≤N 步"）；**实测热轮的两大块**＝读规则/长文（一次读完、别反复翻同义文件）＋同一动作重复（先固化再跑），先压这两块。
   ② **同一命令在一处重复调用，就把「路径与参数」硬化** —— 输出路径**一律绝对路径**（实测反面：`--out` 用相对路径，4 张产物落进库根）；默认参数写成脚本常量，别每次重猜（实测反面：同一参数误用默认值，4 张返工）。
   ③ **隔离胜过小心删** —— 长循环/批处理先落临时目录再做，事后无需清理（隔离运行根是第 6 条，这里补「默认就这么干」）；`job_output` 同一 job **轮询 ≤2 次**，等就等，不要反复看。
   ⚠️ 本条**不要求**改计步口径：探针取的是日志事实，你自数的「轮/步」跟它对不上时，**以日志为准**，也别为了好看改自己的计数。
