# mingmem 接口规范（mmp/1）

> **这是对外契约，不是建议。** 壳、插件、Agent、别的项目想依赖这个内核，就按这份文件接；
> 内核不替调用方写它自己的适配层。本文件由人读，代码零引用（洁净内核原则），
> 但里面的字段名、kind 枚举、信封结构都是**稳定 API**。

- 协议版本：`mmp/1`　｜　软件版本：`0.3.3`　｜　投影 schema：`5`
- 生效日期：2026-10-27

---

## 1. 三个版本号，别混

| 版本 | 含义 | 什么时候变 | 调用方要做什么 |
|---|---|---|---|
| `mmp/1` | **协议**：信封、op、错误分类 | 破坏性改动才升大版本 | 启动时 `hello` 协商；不认识就降级或报错 |
| `0.3.3` | **软件**：命令与行为 | 加命令/改行为/改检索门槛 | 用 `capabilities` 探测，不要写死版本号 |
| `schema_version = 5` | **投影**：SQLite 表结构 | 投影结构变化 | **不用管**：不匹配会自动全量重建 |

**兼容规则（v1 内）**：
1. 只增不改：新命令、新参数、新 kind 可以加；已有字段的语义不改、不删。
2. 调用方**必须忽略不认识的字段**（响应里出现新字段不算破坏）。
3. 调用方**不得**依赖字段顺序、不得解析 `text`/`err` 里的中文（用 `kind` 判断）。
4. 不认识的 op → `kind = "unsupported"`；不认识的命令 → `kind = "not_found"`；都不许崩。

---

## 2. 三层选哪层

| 层 | 形态 | 适合 | 不适合 |
|---|---|---|---|
| L1 CLI | `python -X utf8 -m mingmem <cmd>` | 人、脚本、一次性任务、CI | 高频调用（每次一个进程）、需要结构化结果 |
| L2 serve | `serve --stdio`（JSON Lines） | 常驻宿主、跨语言、插件、批量 | 需要人读的输出 |
| L3 Python | `MemoryCore` | 同进程、同语言 | 跨语言 |

三层是**同一个行为**：L2/L3 都是转调 L1，不复制业务逻辑。所以你不需要为不同层写两套参数。

**机器调用优先 L2/L3，不要刮 L1 的文本输出**。

## 3. 十条通用契约（违反会踩坑）

1. **命令表驱动**：先 `capabilities` 拿命令清单，再 `describe` 拿参数表；不要凭记忆写参数名。
2. **参数名 = `describe` 里的 `name`**（即 argparse 的 `dest`，例如 `out`、`exclude_tag`、`dry_run`）。
3. **字符串参数也接受数组**：传 `{"tags": ["a","b"]}` 与 `{"tags": "a,b"}` 等价（内核按逗号拼接）。
4. **未知参数报 `usage` 错误，不静默丢弃** —— 拼错参数名你会立刻知道，而不是"看起来成功了"。
5. **失败必须当成失败处理**：`ok=false` / 抛异常 / 非零退出码。不要用"输出里有没有字"判断成功。
6. **必须显式给 `ns`**（或依赖数据根配置里的 `default_ns`）。内核不猜项目名，猜错等于记忆串味。
7. **不得假设 `recall` 返回 `limit` 条**：去冗余（MMR + 硬簇上限）常常少给，甚至 0 条。
   0.2.1 起又加了**最低相关分门槛**：没有任何词面证据的条目一律不返回，所以「的」「怎么」这类查询
   就是 0 条（这是正确结果，不是故障）。要看某条"为什么没返回"，读 `items[].evidence`（0 表示无词面证据）
   与 `gate`（`candidates/lexical/dropped_no_evidence/dropped_score/filled`）。
   `items[].filler=true` 表示这条是**图扩散补位**的线索（词面证据为 0），不是命中；
   0.3.0 起还有 `items[].dense_sim`（与查询的余弦，无稠密通道时为 0）；调用方可以按需过滤掉它。
8. **写操作要带 `client_key` 才可安全重试**（目前 `add` 支持）；没有幂等键就假设"可能写了两条"。
9. **披露等级是硬约束**：`private` 默认不检索不导出；`ask` 必须显式 `include_ask=true`，
   且每次展示都会写一条 `consent` 审计事件（含 query 与被展示的 id）。**不要把 `include_ask` 设成默认**。
10. **数据根必须显式**：`init --data-root` 写用户级配置，或每次传 `data_root`。没有配置时所有命令
    退出码 2 —— 这是设计（隐式默认猜错的后果是"记忆变空"，比报错更糟）。

## 4. 握手与能力探测

L2 的第一个请求应该是 `hello`（可选带 `capabilities:true` 一次拿全）：

```
→ {"id":1,"op":"hello","protocol":"mmp/1","capabilities":true}
← {"v":"mmp/1","id":1,"ok":true,"code":0,"kind":"ok",
   "data":{"protocol":"mmp/1","version":"0.3.3","schema_version":5,
           "ops":["hello","ping","capabilities","describe","call","batch","exit"],
           "capabilities":{...}}}
```

协议大版本不匹配时 `ok=false, kind="unsupported"`，但 `data` 里仍会给出服务端支持列表 ——
方便你决定"降级"还是"报错退出"。

> **「大版本」的判定口径**：`mmp/<数字>` 里 `/` 后的整数位。`mmp/1`、`mmp/1.3` 兼容同一大版本；
> `mmp/9`、`mmq/1` 都算不兼容（0.2.2 修：以前只比 `/` 前的标签，等于永远相等，`mmp/9` 会被放过）。

`capabilities` 的要点：

| 字段 | 用途 |
|---|---|
| `commands` | 命令名 → {summary, writes, remote, json}。`writes=false` 的可放心高频调 |
| `errors` | 错误分类表（见 §7） |
| `limits` | `max_limit`（50）、`default_limit`（5）、`max_batch`（50） |
| `layers` | 三层的入口写法 |
| `contracts` | 上面 §3 的机器可读版本 |

## 5. 参数模型（`describe`）

```
→ {"id":2,"op":"describe","command":"recall"}
← {"data":{"recall":{
     "summary":"检索并输出六段结构化 briefing","writes":true,"remote":true,"json":true,
     "params":[
       {"name":"query","kind":"string","cli":["--query"],"positional":false,"required":true},
       {"name":"limit","kind":"integer","cli":["--limit"],"required":false,"default":5},
       {"name":"dry_run","kind":"boolean","cli":["--dry-run"],"required":false},
       {"name":"ns","kind":"string","cli":["--ns"],"required":false},
       {"name":"min_score","kind":"number","cli":["--min-score"],"required":false}
     ],
     "notes":["默认会写一条 access 事件…","返回值条数常常少于 limit…"]}}}
```

规则：
- `kind` ∈ `string / integer / number / boolean / enum / string(positional)`；`enum` 时带 `choices`。
- `positional=true` 的参数按 `describe` 顺序放在命令行末尾（例如 `import` 的旧库路径）。
- `accepts_list=true` 表示可以传数组。
- `required=true` 的参数缺失 → `kind="usage"`。
- **参数表的唯一来源是 argparse**，所以"文档说的"和"实际能用的"不会漂移（自检 P1 项盯着）。

## 6. 调用模型

### 6.1 单条

```
→ {"id":3,"op":"call","command":"add",
   "params":{"text":"决定用事件流做真相源","kind":"decide","tags":["架构"]},
   "ns":"project:demo"}
← {"v":"mmp/1","id":3,"ok":true,"code":0,"kind":"ok","retryable":false,
   "data":{"id":"deci-261026234631-3d2d"},
   "text":"{...原样文本...}",
   "meta":{"duration_ms":12,"wrote":true},"argv":["add","--kind","decide"]}
```

响应字段：

| 字段 | 含义 |
|---|---|
| `v` | 协议版本 |
| `id` | 原样回显你的 id（**用自己的 id 关联，不要靠顺序**） |
| `ok` / `code` | 是否成功 / 原始退出码（0/1/2） |
| `kind` / `retryable` | 错误分类（§7）；`retryable=true` 才值得重试 |
| `data` | 输出能解析成 JSON 时的解析结果（**优先用这个**） |
| `text` | 命令的原样文本输出（给人看/兜底） |
| `err` | stderr（失败时） |
| `meta` | `duration_ms`、`wrote`（这条调用写没写数据） |
| `argv` | 实际执行的参数数组（排查用；**不要依赖它做接口**） |

### 6.2 批量

```
→ {"id":4,"op":"batch","stop_on_error":false,"items":[
     {"id":"a","op":"call","command":"status"},
     {"id":"b","op":"call","command":"links","params":{"id":"node-1"}}]}
← {"ok":false,"kind":"batch_partial","results":[{"id":"a","ok":true},{"id":"b","ok":false,"kind":"not_found"}]}
```

- **顺序保证**：`results` 与 `items` 一一对应、顺序一致。
- `max_batch = 50`；超了直接 `usage` 错误。
- 默认"跑完全部再返回"；`stop_on_error=true` 时遇到第一个失败就停（剩余的不出现在 results 里）。
- 没有跨条目事务：`ok=false` 只表示"至少一条失败"，不回滚已成功的写操作。

## 7. 错误模型

`kind` 是**稳定枚举**。调用方只认它，不解析中文：

| kind | 退出码 | 可重试 | 含义 | 典型处理 |
|---|---|---|---|---|
| `ok` | 0 | — | 成功 | — |
| `usage` | 2 | 否 | 参数拼错/缺参数/非法枚举 | 修调用（别重试） |
| `invalid` | 2 | 否 | 参数合法但被业务规则拒绝（空正文、来源不足） | 改内容 |
| `config` | 2 | 否 | 数据根缺失/配置冲突 | 先 `init` 或加 `force` |
| `not_found` | 2 | 否 | id/文件不存在（可能已真删） | 重新检索拿 id |
| `conflict` | 2 | 否 | 状态冲突（未软删就真删、来源已巩固） | 先 `forget` / 加 `force` |
| `busy` | 2 | **是** | 数据根被别的进程占着 | 退避重试 |
| `storage` | 2 | **是** | 投影损坏/旧库不可读 | `rebuild` 后重试 |
| `findings` | 1 | 否 | 体检发现问题（doctor/verify） | 读明细修数据 |
| `unsupported` | 2 | 否 | 不认识的 op / 协议大版本不匹配 | 降级或升级 |
| `failed` | 2 | 否 | 未分类失败 | 当作缺陷上报（附 `argv`/`err`） |

`retryable=true` 时才重试，**并且写操作要先确认幂等**（§8）。

## 8. 幂等与重试

- `add` 支持 `client_key`（任意字符串，建议"调用方名+业务 id"）。同一个 key 再调：
  **不写第二条**，返回同一条的 id，并带 `idempotent: true`。
- 可安全重试：`status / search / recall(dry_run) / links / bin / doctor / verify / describe / capabilities`。
- 有条件重试：`add`（必须带 `client_key`）、`forget / restore / purge`（重复执行结果一致，
  但会对同一条重复写审计事件）。
- 不要重试：`consolidate / correct / import`（会重复产生结论或事件）。重试前先查 `status` / `verify`。

---

## 9. 分页与限额

- `max_limit = 50`：超过会被夹到 50 并在 stderr 告警（不是报错）。
- `bin --limit/--offset`：回收站的唯一列表入口，返回 `total`（符合条件总数）与 `count`（本页条数）。
- `search --limit`：调试用原始命中；`recall --limit` 是"最多给几条好消息"，同样**不保证条数**。
- 需要遍历大库：用 `export` 导视图**给人看**；用 `search/recall` 分主题取；
  **不要**用 `limit=100000` 拉全库（被夹到 50，你会误以为库很小）。

---

## 10. 并发与锁

- **写是串行的**：命令级拿数据根目录锁（`.mingmem-lock`，可重入，带心跳）。
- 读也要拿锁（可能触发投影重建），所以"多读"不是完全并行，但都是毫秒级。
- 多进程并发写是安全的（10 进程同时 `add` 已实测：全部成功、无半行、无残留锁）。
- **不要**同时 `purge` 与 `add`（真删要重写事件文件）；不要并发 `correct` 同一条。
- `serve` 内部**逐条串行**执行请求：它不是并发服务器。需要并发就开多个进程（锁保证安全）。

---

## 11. 编码

- **机器接口一律 UTF-8**：`serve` 的 stdin/stdout 由服务端强制成 UTF-8，与你的控制台代码页无关；
  JSON Lines 按 RFC 8259。前端写 UTF-8 就一定对，不会因为 Windows 控制台是 cp936 而乱码。
- **CLI 文本输出跟随控制台编码（locale）**，给人看。要在脚本里按 UTF-8 读走 CLI 文本，
  自己设 `PYTHONUTF8=1` 或 `PYTHONIOENCODING=utf-8`；或者干脆用 L2/L3 拿结构化结果。
- 内核内部起子进程时**自己**钉 `-X utf8` + `PYTHONUTF8=1` + `PYTHONIOENCODING=utf-8`，
  不依赖调用方的记性（这条以前踩过：普通 PowerShell 下 `selftest` 会 rc=1）。

## 12. 生命周期

```
启动宿主 → hello(协商) → capabilities/describe(可选，缓存) → [call|batch] × N → exit 或 EOF
```

- `ping` 用于探活（不碰数据）。
- `exit` 或 stdin EOF 正常退出，退出码 0。
- `init` 一生只做一次；重复 `init` 返回 `conflict`，要换数据根加 `force=true`。
- 升级内核后：调用方不需要迁移数据（`schema_version` 会自动重建投影）；
  但**缓存的 `describe` 结果应当失效重取**（软件版本变了）。

---

## 13. 安全与披露

- 没有网络、没有 HTTP：所有接口都是本机进程间（stdio / 同进程）。
- 数据根里是**明文**记忆（`events/*.jsonl`）：安全边界 = 文件系统权限，不是内核。
- `private`：默认不检索、不导出；要出现必须显式 `include_private=true`（仅 `export` 支持）。
- `ask`：必须显式 `include_ask=true`，且每次展示写 `consent` 审计；审计**不进节点表**、不参与检索。
- 真删（`purge`）不可逆：调用方必须自己先做二次确认（`dry_run=true` 干跑 → 用户确认 → `yes=true`）。
- **审计类事件不许由调用方伪造**：`add` 拒绝 `consent/forget/restore/purge/access/sweep/archive/link/correction/consolidate`。
  迁移历史用 `import`（唯一例外：它读的是旧库，不是手写事件）。

## 14. 各类调用方的接入清单

### 14.1 桌面壳 / GUI
1. 先 `capabilities` + `describe`，据此**生成**表单/菜单，不要手写命令列表。
2. `writes=false` 的命令可以随便预取；`writes=true` 的要显式用户动作。
3. 展示 `ask/private` 前必须过 §13 的规则，并把 `consent` 审计 id 留在日志里。
4. 删除走 `forget`（可撤销）→ `bin` 复核 → `purge --yes`（不可逆），中间必须有一步人工确认。

### 14.2 插件（未来 DSH 插件壳）
1. 壳只做适配：config → 数据根、内核能力 → 工具/服务；**内核零 DSH 依赖**（已满足）。
2. 壳**不得**直连 `index.sqlite`，只经 L2/L3。
3. 插件启动时 `hello`；找不到数据根就报"未配置"，**不要自己造一个默认目录**。

### 14.3 Agent / 工具定义
1. 用 `describe` 直接生成工具 schema（`name/kind/required/choices` 都齐）。
2. 把 `capabilities.contracts` 原样塞进系统提示，避免模型编参数。
3. 记住三条硬约束：必须给 `ns`；不要假设条数；写操作尽量带 `client_key`。

### 14.4 脚本 / CI
1. 用 L1 就设 `PYTHONUTF8=1`；判成功只看退出码。
2. 需要结构化结果时用 `--json`（支持矩阵见 `capabilities.commands[*].json`）。
3. 破坏性操作先跑 `--dry-run`。

### 14.5 别的项目（例如学习库）
1. 先 `import` 迁旧库（`dry_run` 看清单，再真导），再用 `init --data-root` 指向自己的数据根。
2. 每次调用显式给 `--ns project:<项目名>`（别用默认反推）。
3. 你们的封装、看板、调用约定是**你们自己的事** —— 内核只提供上面这些接口。

## 15. 改内核时要动哪些地方（维护规则）

新增/修改一个命令的最小清单：

1. `cli.build_parser` 加参数（**参数唯一来源**）；
2. `spec.COMMANDS` 加语义（summary/writes/remote/notes/examples）；
3. 需要 `--json` 的进 `settings.JSON_SUPPORTED`；
4. `commands.py` 实现（写进 `api.py` 不行 —— 那里只转发）；
5. `tests.py` 加自检项（P1 项会自动校验"describe 与 argparse 零漂移"）；
6. 文档：本文件的相关小节 + `操作手册.md` 的命令小节；
7. 版本号：改行为就升 `settings.VERSION`，并出一份 `_Archives/记忆内核/Backups/mingmem_V<版本>/`。

---

## 16. 明确禁止（会被当成缺陷）

1. 直接读写 `index.sqlite` 或裸读 `events/*.jsonl` 当接口 —— 那是内部实现，随时会变。
2. 解析 `text`/`err` 的中文来判成功/失败 —— 用 `ok`/`code`/`kind`。
3. 依赖 `argv` 字段拼自己的调用 —— 那是排查用的回显。
4. 假设 `recall` 一定返回 `limit` 条、假设 `status` 的节点数等于事件数。
5. 调用方自己"猜"数据根或命名空间。
6. 给 `add` 塞审计/派生事件类型（`consent` 等）伪造历史。
7. 用 `--include-ask` 当默认值。

## 17. 变更记录（只记调用方需要知道的）

| 软件版本 | 变更 | 调用方要做什么 |
|---|---|---|
| `0.2.0` | 落地协议 `mmp/1`：三层接口、`capabilities`/`describe`、`call`/`batch`、`kind` 枚举、`client_key` 幂等 | 按本文件接 |
| `0.2.1` | `recall` 增 `--min-score`；返回更少条是常态；`items[]` 增 `evidence`/`boundary`/`filler`，顶层增 `gate` | 别把"返回 0 条"当故障；有 `filler` 时按需过滤 |
| `0.3.3` | 修 `doctor` 在**空数据根**（尚无事件与投影）上的崩溃：稠密通道那行引用未绑定的节点数，抛 `UnboundLocalError`（rc=1 + traceback）；顺带去掉它对空库的写副作用（不再凭空生成 `index.sqlite`）。自检 79→81 | 新库首次体检不再崩；`doctor` 现在是纯只读 |
